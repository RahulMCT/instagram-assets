🔐 HxGN EAM Role Security CHEAT SHEET
One login, many roles: switch between purchasing, scheduling and admin views without logging out. (Infor EAM 11.6.1 Role Security brief)

1. What & why

  • One User ID with multiple Roles in the same Organization
  • Each Role = its own permissions, menus, screens, page layout
  • No more duplicate logins per job function
  • Available from Infor EAM 11.6.1

2. Before vs after

  • OFF: User + Org → exactly one User Group (1:1)
  • ON: User → Role → User Group + Org (1:many)
  • Same Org can appear more than once on the User's Organization tab
  • Biggest win: users doing several functions in one Org

3. Enable it

  • Install parameter ROLESECU = ON
  • Not shipped — the admin must create it
  • Needs MULTIORG = YES (multi-org security)
  • MULTIORG off → no Switch Roles button

5. Role Setup screen

  • Each Role links a User Group + an Organization
  • Product permissions: base app, mobile apps…
  • Role Limits: Requisition, Invoice, PO + approval limits
  • Permissions still read from User → Organization tab, via the Role's group

6. Default Role *

  • System role, always available
  • Shipped with the R5 User Group under the * Organization
  • Role * = menus + layout from the User record's group
  • So switching ON doesn't break existing users

7. DEFORG rule

  • Every Role needs access to the default Org (DEFORG)
  • Add a non-DEFORG row → EAM auto-inserts a DEFORG row (same Role + group)
  • Delete the DEFORG row → remove the Role's other rows first

8. User experience

  • Switch Roles in System Links → pick a Role, no logout
  • About link shows the current Role (even when OFF)
  • Reports only include data for the current Role's Orgs

9. Disabling Role Security

  • Set ROLESECU to any value other than ON
  • Blocked while any user has the same Org more than once on the Organization tab: clean those rows first
  • After disabling, every user's Role resets to the default *

10a. Flow

MULTIORG=YES→ROLESECU=ON→Role Setup→Assign on User→Switch Roles

10b. Consultant tips

  1. Check MULTIORG before creating ROLESECU
  2. Design Roles by job function, not by person
  3. Replace duplicate per-function logins
  4. Plan the duplicate-Org cleanup before disabling

10c. Key points

  • Create ROLESECU
  • Role = Group + Org
  • * = old behavior
