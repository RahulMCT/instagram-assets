Call Center & Service Requests Cheat sheet
From the help desk call to a validated service request, work order, case and follow-up.

1. What it is

  • Call Center collects service requests: phone, e-mail, fax, or self-service via the Service Request Portal
  • Simple ask (office hours) → record, answer, close
  • Serious ask (chemical spill) → work order + regulatory case
  • Help desk lives on the Call Center screen

2. Service Code Validation (per org)

MethodMatrix lives on
Department StructureDepartment → Structure tab (Supplier › Service Category › Service Code); pick Department before Equipment
SDMEquipment → Service Delivery Matrix tab (tick the SDM checkbox first); Equipment first
Simplified SDMSupplier ↔ Service Code once, then link to equipment; no Department / Category

3. SDM roll-down

  • Parent matrix applies to children only if the child has no own SDM records
  • Child must still have the SDM checkbox ticked, else lookups stay empty (Department excepted)
  • All-Departments (and similar) checkboxes save records
  • Simplified SDM shows which parent a record came from; skip or stop roll-down

4. Service Codes screen

  • A template WO, template case, or both
  • Temporary / Permanent Fix Turnaround → promise dates
  • Standard Response Time → Deadline (Hours to Deadline refreshes every minute)
  • Equipment Usability, Penalty (EAM does not calculate penalties)
  • Tabs: Case Tasks, Equipment Classes (clears General), Suppliers, Equipment, Supplier Exclusions

5. Follow-up work

  • For Follow-up codes can't have follow-ups themselves (no recursion)
  • Follow-up Timing: No follow-up Work · Service Request Follow-up · Work Order Completion · Work Order Creation
  • Only for WOs created from the Call Center, not linked ones

6. How the WO is built

1) Standard WO → use it 2) else Task Plan (+Job) → 1 activity 3) else Trade + Est. Hours + People 4) else header only, no activity
  • WO Type / Class / Priority on the code override the Standard WO
  • Auto Create WO: on insert only, no duplicate check

7. Call Center Setup

  • Defaults: Source CRSC, Type COTP, Status COST (+ Portal variants)
  • WO org: SR org → Service Code → Equipment → WO Class → Default WO Org.
  • Open / Follow-up Request Status when WO Closes
  • Allow Request to be Closed while WO is Open · Allow New Contact to be Saved

8. Duplicate & recurring checks

  • Enable Duplicate WO Check: link existing or create new
  • Days to Show Closed WOs: blank none · 0 today · 1 today + yesterday
  • Filter by WO Types / Statuses, match header equipment, Service Category, Service Code
  • Check Duplicate Open / Recurring Closed Requests (same equipment + service code) + Lookback Days
  • Duplicate Request set → no WO can be created or linked

9. Knowledge base & bulletins

  • Article: Keywords (case-insensitive), Article Text with hyperlinks, Status KBST
  • Keyword vs Full Text search; with SDM, Equipment first
  • KBAVALRV = YES flips the Service Code Validation Filter default
  • Top 10 articles need the Top 10 Knowledge Base Article Driver job
  • Notices: Start/End Date, Importance High › Normal › Low

10. Call Center screen

  • Find Contact By / Global Search; phone search strips non-numeric characters
  • Campus › Building › Floor › Room/Unit; lowest level → Equipment
  • Create WO link is protected; linked WO stays editable (Duplicate WO)
  • Auto Request Case → case in requested status; Priority SRPR, VIP VIPS
  • Create New Service Request keeps the contact

Flow

Contact→ Equipment→ Service Code→ KB search→ Duplicate check→ Create WO / Case→ Follow-up

Consultant tips

  1. Choose the validation method per org before loading data
  2. Auto Create WO / Auto Request Case can create more records than you need
  3. Portal users need Service Categories set up

Key points

  • Multiple equipment not allowed with SDM
  • WO fields copied once, not synced later
  • Close a request → its duplicates close too
