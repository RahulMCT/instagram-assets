📢 HxGN EAM Bulletins CHEAT SHEET
Push important messages to users inside EAM, force acknowledgement for critical ones, and track who read them. (HxGN EAM Bulletins brief, 12.1.1)

1. What is a bulletin?

  • A message users must see and acknowledge
  • Planned upgrades, emergency maintenance notices, system updates
  • Admin creates it, picks recipients, tracks who acknowledged

2. Bulletin Setup (record)

  • Description, Status, Start / End Date, Critical
  • User Defined Fields for admin tracking
  • Tabs: Message, Recipients, Acknowledged

3. Status rules

StatusEdit?
InactiveRecord + tabs editable
ActiveLocked (set back to Inactive to edit)
Expired ✔System sets it after End Date; no more edits
Only Inactive / Active. No customer-defined statuses.

4. Before you can Activate

  • At least 1 message in the Default Language (DEFLANG)
  • At least 1 recipient on Recipients tab
Miss either one and Active is blocked.

5. Message tab

  • One message per language
  • Plain text or HTML (images, links, colors)
  • HTML needs install parameter HTMLCOMM = ON

6. Recipients tab

  • Add by User or by User Group (both allowed)
  • Each user / group becomes its own record

7. BULLOGIN install parameter

ValueOn login
ALLPop-up if any bulletin to review
CRITPop-up only for Critical ones
NONENo pop-up, icon still shown
OFF (default)Feature disabled, no icon

8. User side

  • Bulletin Notification icon (header, top right) with a count
  • Bulletin Display pop-up: Critical can't be closed until Acknowledge
  • Acknowledged tab logs user, date, language
  • Bulletin History screen = my acknowledged bulletins

9a. Bulletin flow

Bulletin Setup (Inactive)→Message + Recipients→Active→Acknowledge→Expired

9b. Consultant tips

  1. BULLOGIN is OFF by default: switch it on first
  2. Editing a message deletes its old acknowledgements
  3. Use Critical only for must-read notices
  4. Web browser only in 12.1.1 (not mobile apps)

9c. Key points

  • DEFLANG msg + 1 recipient
  • Active = locked
  • CRIT = login pop-up
