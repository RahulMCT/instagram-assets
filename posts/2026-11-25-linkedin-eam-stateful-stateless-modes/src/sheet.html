Stateful vs Stateless Modes Cheat sheet
Sticky sessions in JVM memory, or any JVM plus a Couchbase cache. Here is the setup.

1. Two session modes

ModeHow sessions work
Stateful (default)Sticky sessions ON, session kept in JVM memory
StatelessSticky sessions OFF, any JVM serves any request, session in an external cache
  • Stateless needs EAM on JBoss Application Server

2. Key terms

  • JVM: one process running JBoss + all EAM code
  • Many JVMs: jboss.instances > 1 in extended_properties.xml and/or several installs behind a load balancer
  • Sticky session: session tied to the JVM that created it, via the JSESSIONID cookie

3. Which one to pick?

StatefulStateless
No extra cache app to buy, run or maintainSupports Zero Downtime Upgrades (ZDU)
No extra servers, RAM, fast networkAdd/remove JVMs dynamically with load

4. Couchbase cluster rules

  • Stateless cache = Couchbase Server (distributed cache)
  • EAM won't run if Couchbase is down → plan redundancy
  • Min 2 nodes, with replication; one node per (virtual) machine
  • EAM and Couchbase on different machines; all nodes same 64-bit OS
  • Same LAN, static IP (dynamic IP + default config = unusable node)

5. Memory & install

  • Same Couchbase RAM on every node, no virtual memory
  • Min 4GB per node (half data, half replicas) → VM with 8GB+
  • Brief names version 5.0.1, 64-bit, Community or Enterprise
  • Admin UI: http://server:8091 → Start a New Cluster, Data Service quota ≥ 4096MB, bucket type Couchbase
  • 2nd server: join cluster → Server Nodes → Rebalance (even when empty)

6. extended_properties <eamcache>

statetype = stateless externcachehost = IP of Couchbase node 1 (required) externcachehost2 = IP of node 2 (optional, recommended) bucket / bucketPassword = blank if 'default' bucket sysrefreshcache = 5–60 min (false → 15 min) oldbaseuri = used for ZDU

7. Clusters & shared paths

  • All EAM instances in one cluster → same Couchbase cluster
  • Unrelated installs (PROD / TEST / TRAIN) → own Couchbase cluster each
  • MPConfiguration.xml.vm paths on a network share: fm-definition.base-dir, attach-definition.base-dir, DocUpload.UPLOADDIR, ExportConfig.ExportConfigDir
  • Databridge: move Document.home, keep Configuration.home

8. Load balancer & SSO

  • Proxy must not enforce sticky sessions on JSESSIONID in stateless mode
  • Proxy must rewrite EAM redirects to its own address, or browsers bypass it
  • SSO: AppServerHost and logonURL point to the LB, not the app server
  • sp.xml.tmpl: proxy host:port, https, keep @BASE_URI@; new base URI → new ADFS Relying Party

Flow

Build 2+ node Couchbase→ Rebalance→ <eamcache> stateless→ Shared file paths→ LB: no sticky

Consultant tips

  1. Always fill externcachehost2
  2. Use IPs, not names, for cache hosts
  3. Light non-PROD: 1 node, no replication is OK

Key points

  • Stateful is the default
  • Stateless = JBoss + Couchbase
  • No cache, no EAM
