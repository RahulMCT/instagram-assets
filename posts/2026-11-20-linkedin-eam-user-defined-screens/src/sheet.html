User Defined Screens Cheat sheet
Build your own List View / Record View screens and tabs: fields, keys, SQL values, then Generate.

1. What it is

  • Build custom screens inside EAM from fields you define
  • Each screen is stored as a table in the database
  • User Defined Screens = standard List View / Record View screen
  • For system admins + power users with database design know-how

2. Naming rules

Screen Name : 6-char code, 2nd char = 'U' unique, no special chars Table Name : unique in EAM schema, no special chars → prefixed U5 Entity : optional → prefixed $

3. Entity, tab or menu

  • Entity entered → auto Description field + Comments and Documents tabs
  • Tab → choose the Parent Screen
  • Otherwise → List View / Record View screen for the menu
  • Out of Service: hidden from lookups + Menus / Scanner Menu tabs on User Groups; existing menu entries stay (remove manually)

4. Fields tab basics

FieldMeaning
Field NameActual column name; unique, no reserved words, no special chars
DescriptionDetailed name / definition
Field LabelLabel on screen (screen designer later)
SequenceOrder of the field on the screen

5. Field types

TypeEnables / stored as
AlphabeticField Length + optional Uppercase
NumericTotal Digits (both sides) + Decimal Places
Free Format TextGeneral text / comments, CLOB
Checkbox · Date · Date Time · TimeStandard types

6. Keys & flags

  • Is Primary Key: unique record id, one field or a combination
  • Is Nullable: can be blank; protected + unselected on a PK field
  • Uppercase: Alphabetic only, value must be uppercase
  • Field-level Out of Service: currently not used

7. Computed Value

  • Enables Computed Data: SELECT runs when the record is saved
  • Generated as a protected field; Oracle + SQL functions allowed
SELECT sysdate FROM dual -- field with Sequence 3 = :3 SELECT per_desc FROM r5personnel WHERE per_code = :3

8. Retrieved Value & lookups

  • Source Field fires the query when the user leaves it
  • Retrieved Value Query = SELECT from the Queries screen
  • Query Code makes a lookup (Data Collection, Normal or Lookup queries)
-- installed assets only SELECT obj_code, obj_desc FROM r5objects WHERE obj_obrtype = 'A' AND obj_status = 'I'

9. Parent Screen Key Field

  • Tabs must bind rows to the header, else they show on all headers
  • Parts tab example: Part Code + Part Organization + 1 unique field
  • = 3 primary key fields on the Fields tab
  • Key fields can be hidden with screen designer

10. Generate

  • Record View → Generate → confirmation → generation starts
  • Creates a new function + new database table
  • One generic web service for Insert / Update / Delete, not on Web Service Prompt (BSWSPM)
  • After generation, edits are limited

Flow

Screen Name→ Table (U5)→ Entity? Tab / Menu→ Fields tab→ Generate→ Menu / Tab

Consultant tips

  1. Finalise fields + keys before Generate
  2. Reference other fields by Sequence (:3)
  3. Fine-tune labels in screen designer

Key points

  • 2nd char of code = 'U'
  • Table → U5 · Entity → $
  • Free Format Text = CLOB
