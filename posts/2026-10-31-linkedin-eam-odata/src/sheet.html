🔗 HxGN EAM OData Services CHEAT SHEET
REST with a data model: discover, query and update EAM records with plain HTTP. (HxGN EAM OData: Open Data Protocol, 12.3)

1. What is OData?

  • Open Data Protocol: REST-based data services
  • Resources identified by URIs inside a data model
  • Core idea: the Entity Data Model (EDM)
  • Supported in EAM since 12.1

2. Two discovery docs

DocumentGives you

/axis/odataservices		All supported entity names + URLs (JSON)

Both work without tenant or user credentials: no DB call.

4. Keys in the URL

  • Key names come from $metadata
  • Strings in single quotes, numbers without
…/odataservices/Lots(
LOTCODE='L1',
ORGANIZATIONCODE='ORG1')
…/odataservices/Tasks(
TASKCODE='TP1',TASKREVISION=0,
ORGANIZATIONCODE='ORG1')

5. Query options

  • Only on Get Collection
  • Supported: $filter $count $top $skip
  • Collection = entity's default Dataspy
?$count=true → "@odata.count"
?$top=3 → first 3 rows
?$skip=2 → from 3rd row on

6. $filter syntax

  • eq ne gt ge lt le · and or not
  • contains / startswith / endswith
…/Lots?$filter=startswith(
LOTID/ORGANIZATIONID/
ORGANIZATIONCODE,'AOR')
No filters yet on DATETIME, QUANTITY, AMOUNT. Encode # as %23.

7. Headers (Postman)

tenant = <TenantName>
organization = <ORGCODE>
parentid = <CODE#ORG>
  • parentid only for tab entities
  • Credentials in the Authorization tab
  • Body JSON in, JSON out (like REST)

8. Date gotcha

  • YEAR must be YYYY in requests + responses
  • Epoch milliseconds are not supported
"COMMISSIONDATE": {
"YEAR": 2025, "MONTH": 7, "DAY": 28,
"HOUR": 0, ..., "TIMEZONE": "+0530" }
