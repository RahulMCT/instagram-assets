🍃 Spring Boot Transactions CHEAT SHEET
Transactional annotation = AOP proxy wraps your method: begin → commit on success → rollback on RuntimeException by default.

1. What & why

  • A transaction = all-or-nothing unit of DB work
  • ACID: Atomic · Consistent · Isolated · Durable
  • Without it: half-updated rows, dirty money transfers
  • Spring Boot auto-enables tx when a DataSource exists

2. How it works (AOP)

Caller→Proxy→begin→your method→commit / rollback
  • Annotation triggers a Spring AOP proxy
  • Only works when called through the proxy
  • EnableTransactionManagement is on by default in Boot

3. Propagation (the big table)

ValueBehavior
REQUIREDjoin existing, else create (default)
REQUIRES_NEWsuspend + always new tx
SUPPORTSjoin if exists, else non-tx
MANDATORYmust join; else error
NEVERerror if a tx exists
NOT_SUPPORTEDsuspend existing; run non-tx
NESTEDsavepoint inside current

4. Rollback rules

  • Default: rollback on RuntimeException / Error
  • Checked exceptions do NOT roll back by default
  • rollbackFor = Exception.class → roll back checked too
  • noRollbackFor = ... → keep commit for listed types
  • readOnly = true → hint for optimization / flush skip

5. Example service

@Service public class TransferService { @Transactional // REQUIRED public void transfer(Long from, Long to, BigDecimal amt) { debit(from, amt); credit(to, amt); // RuntimeException → full rollback } @Transactional(propagation = Propagation.REQUIRES_NEW) public void audit(String msg) { // commits even if outer rolls back } }

6. Self-invocation trap

  • this.transfer() from same class → no proxy → no tx
  • Fix: call via another bean, or self-inject the proxy
  • private / final methods are not proxied (JDK/CGLIB limits)
  • Same for unchecked → checked: annotate carefully

7. Common mistakes

  • Catching RuntimeException inside method → Spring never sees it → no rollback
  • Expecting checked Exception to roll back without rollbackFor
  • REQUIRES_NEW everywhere → too many commits, harder locks
  • Long tx holding DB connections / row locks
  • Calling @Transactional on a non-Spring bean

8. Isolation (quick)

LevelAllows
READ_UNCOMMITTEDdirty reads
READ_COMMITTEDno dirty (common default)
REPEATABLE_READstable rows in tx
SERIALIZABLEfull isolation, slowest
Set via isolation = Isolation.READ_COMMITTED

9a. Decision flow

need atomic?→Transactional→audit must survive?→REQUIRES_NEW→checked fail?→rollbackFor

9b. Interview Qs

  1. Why does self-invocation skip the transaction?
  2. REQUIRED vs REQUIRES_NEW?
  3. Why checked exceptions don't roll back by default?
  4. What does readOnly=true actually do?
  5. How would you roll back on a checked Exception?

9c. Key points

  • Proxy = magic
  • Default = RuntimeException
  • Call via bean
