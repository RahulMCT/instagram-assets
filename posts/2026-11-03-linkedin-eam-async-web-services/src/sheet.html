⏳ HxGN EAM Asynchronous Web Services CHEAT SHEET
New in 12.3: fire the request, get an ID back, let the server queue the work. (HxGN EAM Asynchronous Web Services brief, 12.3)

1. Before 12.3: synchronous

Client request→Server runs it now→Response
  • Every EAM web service call ran synchronously
  • Client waits for the full result

2. From 12.3: asynchronous

  • Server queues requests for later execution
  • Manages workload without immediate processing
  • Runs sync + async requests at more optimal levels

3. The async flow

Client→Web service tier→ASYNCWSID back→Queue→Asynchronous tier

4. Cloud only ☁️

  • Async mode is available exclusively in cloud environments
  • On-premises: an async request is treated as synchronous

5. What runs async

  • The add interface transactions web service is processed in asynchronous mode in cloud
  • A unique request ID, ASYNCWSID, comes back for tracking

6. Track the status

9. Sessions on the async tier (Octave Attune 12.3.1 release notes)

  • Since 12.3.0.2 the session used to submit AddInterface on the web service (axis) tier is reused on the async tier, so fewer sessions are created
  • SG-20010: NoSessionException seen on the async tier when SessionScenario is set to terminate
  • SG-18110: async PATCH asset requests reusing one session hit "IJ031050: The result set is closed"

10b. Consultant tips

  2. Log every ASYNCWSID
  3. Retest session handling after patches
